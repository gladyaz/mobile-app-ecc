# Offline Android Demo APK — internal build notes

**This is an internal demo build. It is NOT a production or store release.**

It is the artifact handed to someone who has **no backend, no LAN, no account
and no internet** — a founder or partner opening the app on their own phone.
It runs the real app code against bundled content.

> **This is not the only demo APK.** [android-local-demo.md](./android-local-demo.md)
> describes a *different* artifact: a LAN-backed build that talks to a local
> NestJS backend over plain HTTP and requires `EXPO_PUBLIC_DEMO_MODE=false`.
> The two are not interchangeable, and §7 below is the honest list of what
> this one cannot show.

---

## 1. What this build is

| | |
|---|---|
| Artifact | `android/app/build/outputs/apk/release/app-release.apk` (gitignored) |
| Build type | Gradle `assembleRelease` — JavaScript bundled inside the APK |
| Metro required after install? | **No.** `assets/index.android.bundle` (Hermes bytecode) ships inside |
| Backend required? | **No.** No backend URL is compiled into the bundle at all |
| Internet required? | **No.** Clips and posters are in the APK |
| Signing | The Expo template's local **debug** keystore. Not a production key, deliberately — this artifact must never be mistakable for a store build |
| ABI | `arm64-v8a` only |

`android/` is generated by `npx expo prebuild` and is gitignored, so the APK is
reproduced from source rather than stored.

---

## 2. How to build it

Everything is driven by one gitignored `.env`. `.env.example` documents every
key, including `EXPO_PUBLIC_DEMO_MODE`.

```bash
# .env for THIS artifact
EXPO_PUBLIC_DEMO_MODE=true
EXPO_PUBLIC_USE_MOCK_DATA=false      # demo mode already implies mock data
EXPO_PUBLIC_HLS_PLAYBACK_ENABLED=true
EXPO_PUBLIC_INCLUDE_QA_FIXTURES=false
# EXPO_PUBLIC_API_BASE_URL is DELIBERATELY UNSET - see §4
```

```bash
export JAVA_HOME="/Applications/Android Studio.app/Contents/jbr/Contents/Home"
export ANDROID_HOME="$HOME/Library/Android/sdk"

npx expo prebuild --clean --platform android --no-install
cd android && ./gradlew assembleRelease -PreactNativeArchitectures=arm64-v8a
```

`EXPO_PUBLIC_*` values are inlined by Babel **at bundle time**, so they cannot
be changed after the APK exists. The `.env` must be correct for the Gradle
step, not only for the prebuild step — Gradle is what runs Metro.

**`-PreactNativeArchitectures` rather than editing `gradle.properties`,**
because `prebuild --clean` regenerates that file and would discard the edit.
The property is the template's own documented override (see the comment above
`reactNativeArchitectures` in the generated `android/gradle.properties`).
Dropping `x86`/`x86_64` (emulator-only) and `armeabi-v7a` took the artifact
from ~171 MB to ~107 MB. **It will not run on an x86 emulator.**

## 3. What demo mode changes

One switch, `EXPO_PUBLIC_DEMO_MODE` (`src/services/demo/demo-mode.ts`):

| Surface | Behaviour | Where |
|---|---|---|
| Home feed | Bundled clips, not a backend feed | `services/videos/video-service.ts` |
| Discover / Series | Same bundled catalog, via the shared `shouldUseMockData()` | `services/series/series-catalog-service.ts` |
| Login | Accepts **any** email and password, mints synthetic local tokens | `stores/auth.tsx`, `services/demo/demo-auth.ts` |
| Register / WhatsApp / Google | Hidden on the login screen, and refused in the store even if deep-linked | `app/login.tsx`, `stores/auth.tsx` |
| Ads | Suppressed; the ads bridge is never mounted | `services/ads/ads-config-service.ts`, `app/_layout.tsx` |
| Likes / saves | Stay local; the sync queue never flushes | `stores/video-interactions.tsx` |
| Rewards | Bounded "Rewards belum dibuka" state; **no network call** | `features/rewards/use-rewards-center.ts` |
| `/_sitemap` | Removed from the build entirely | `app.config.js` |

### Why Rewards is dark rather than populated

Every `/rewards/*` route is authenticated and server-authoritative, and the
placeholder economics module was **deleted outright** rather than left
importable (`docs/rewards-domain-contract.md`). There is deliberately nothing
to fall back to, because the one thing this feature must never do is show a
balance it did not get from the ledger.

So an offline build does not fetch. Without that gate a demo viewer who signs
in — and demo login accepts anything — would land on the generic error state
with a Retry button that can never succeed, and, because the API layer has no
timeout, on a permanent spinner whenever a configured host resolves but never
answers.

The state shown is not new copy: it is the **same** `unavailable` state a
`REWARDS_ENABLED=false` deployment produces, already localized in id/en/zh. It
is shown whether or not the viewer is signed in, on purpose — otherwise
signing in would take them *from* a clean "Masuk untuk lihat koin" prompt *to*
a dead end, and signing in is the natural thing to do in a demo.

## 4. There is no cleartext exemption, and no backend URL

`EXPO_PUBLIC_API_BASE_URL` is left unset. Two things follow, both verifiable
from the APK:

1. `plugins/with-lan-cleartext-demo.js` keys off that value's **scheme**, so
   with nothing there it registers no `network_security_config`, no manifest
   attribute, and no exemption. Android's default cleartext-denied behaviour
   is fully intact.
2. Any stray request fails fast with `MISSING_BASE_URL` instead of hanging on
   a host that resolves but never answers.

```bash
# Both should print nothing / 0 for this artifact.
aapt2 dump xmltree --file AndroidManifest.xml <apk> | grep -i networkSecurityConfig
unzip -p <apk> assets/index.android.bundle | strings | grep -E "http://[A-Za-z0-9._-]+:[0-9]+"
```

(The bundle does contain `http://localhost:8081` — that is React Native's
built-in Metro dev-server constant, used only when `BuildConfig.DEBUG` is
true. It is not a backend address, and this is a release build.)

## 5. AdMob metadata is present, and must be

A demo build ships `com.google.android.gms.ads.APPLICATION_ID` in its
manifest, set to Google's published **test** app id. This is not an oversight
and must not be "cleaned up".

`app.config.js` used to strip the AdMob config plugin whenever
`isDemoBuild()`. That was correct only while the demo build *also* excluded
the AdMob native module from autolinking. It no longer does. With the module
autolinked and the plugin stripped,
`react-native-google-mobile-ads/android/build.gradle` resolves the
`appJSONGoogleMobileAdsAppID` manifest placeholder to an empty string, and
`MobileAdsInitProvider` — a `ContentProvider`, so it runs before
`Application.onCreate` and before any JavaScript — **crashes the app on
launch**. That build file carries the warning itself: *"The native Google
Mobile Ads SDK will crash on startup without it."*

The filter is therefore keyed off autolinking, not off demo mode. Keeping the
plugin costs the demo nothing: the ids are test ids, `<AdsBridge/>` is never
mounted in demo mode, and `ads-config-service.ts` reports ads disabled, so no
ad is ever requested.

## 6. No internal surfaces

- **`/_sitemap` is removed.** `expo-router` generates a route that lists every
  route plus a System Information panel (NODE_ENV, Expo SDK version, Hermes
  version), it ships in release builds, and the app declares a URL scheme — so
  it was reachable via `mobileappecc://_sitemap` on an installed APK. Demo
  builds now set `sitemap: false` on the `expo-router` plugin (`app.config.js`),
  which removes it from the root stack and the linking config. It is left
  enabled for `expo start`, where it is a useful dev affordance.
- **`src/app/+not-found.tsx` replaces the built-in "Unmatched Route" screen,**
  which is untranslated English on a light surface, echoes the raw deep link
  back, and renders a "Sitemap" link with `href="/_sitemap"` **hardcoded** —
  it does not read the sitemap setting, so disabling the sitemap does not
  remove the link. Owning the route is the only way to remove it.
- **Processing History** ("INTERNAL · STAFF ONLY") has no entry point: its
  Profile row is hidden in demo mode, and it is no longer listed by
  `/_sitemap`. It remains reachable by manually typed deep link
  (`mobileappecc://processing`); that is a known, accepted residual.
- The QA 16:9 fixture is **not** in the catalog
  (`EXPO_PUBLIC_INCLUDE_QA_FIXTURES=false`). Its two files are still packaged
  (~1.3 MB) because the `require()` calls sit in a top-level initializer —
  dead weight, not reachable content.

## 7. What to say when handing this over

**Works, with no network of any kind:** first launch, guest browsing straight
into Home, playback of ten bundled episodes across two series, Discover and
Series Detail on the same bundled catalog, Saved, Profile, local sign-in, and
likes/saves that persist on the device.

**State these plainly:**

- **Login is not real.** Any email and any password are accepted. No account
  exists and nothing is verified. This build cannot demonstrate authentication.
- **Rewards is dark.** It shows "Rewards belum dibuka". Check-in, the points
  ledger and VIP redemption are implemented and working, but only against a
  backend — see [android-local-demo.md](./android-local-demo.md) for the build
  that demonstrates them.
- **No ads.** Suppressed entirely in demo mode.
- **Google and WhatsApp sign-in are not present** on this build's login screen.
- **The catalog is two series, five episodes each.** Seven of the nine
  Discover category chips are therefore empty, and search covers only those
  two titles.
- **It is signed with a debug keystore,** so Android will warn on install and
  Play Protect may flag it as an unverified sideload. It is also not
  upgradable to any future differently-signed build — uninstall first.
- **arm64-v8a only.** Any modern physical phone is fine; an x86 emulator is not.
- This is **not** a production or store release.
